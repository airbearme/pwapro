## 2026-02-25 - Unprotected Administrative Endpoints and Next.js 16 Middleware Convention
**Vulnerability:** Critical administrative endpoints (/api/setup/*, /api/spots/update, /api/airbear/update-location) were completely unprotected, allowing unauthorized data modification. Additionally, the security middleware was misconfigured or ignored.
**Learning:** In this environment's version of Next.js (16.1.1), the standard `middleware.ts` convention is deprecated in favor of `proxy.ts`. For middleware to execute, it must be named `proxy.ts` and export a function named `proxy`. Administrative protection should be centralized in middleware using timing-safe comparisons of a shared secret (ADMIN_SECRET) to prevent side-channel attacks.
**Prevention:** Always verify middleware naming and execution by checking framework-specific logs and warnings. Use robust environment variable resolution that handles multiple possible naming variants (e.g., standard vs. PWA4) to ensure configuration is always loaded. Provide dummy environment variables in CI to satisfy Zod validation during build-time module evaluation.
